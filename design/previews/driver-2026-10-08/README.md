# ThinThai Driver UX/UI

Created 2026-10-08 using built-in imagegen. Eight mobile concept screens on three boards: login / application / pending approval; available for work / incoming offer / active delivery; delivery confirmation / earnings. Food delivery first. Passenger-service approval is separate. No app code changed.

Fictional maps, orders, people, earnings and proof photographs. Example FD-DEMO-005: customer paid online, no cash collected; gross rider fee60 minus platform10 = net50. Four prior jobs net180, after fifth net230 (gross280 minus fees50). Pending payout230, paidout0. These are design examples, not actual pricing.

Implementation notes: use actual project logo; verify Thai labels and contrast. Map navigation action must be separate from arrival confirmation (the generated map icon on the arrival button should not be used for navigation). Generated timestamps repeat09:42 across acceptance/latest job; replace with actual event-specific timestamps in implementation. Login OTP flow and remaining application steps are not detailed in this board. Only approved eligible riders may go online. Validate offer expiry/acceptance atomically on server. Completion, customer payment, cash reconciliation and rider payout are separate states. Upload delivery proof before final completion with retry recovery. Show contact controls only for authorized active jobs. Do not treat generated map as real routing. Tablet/desktop adaptation, error states, offline recovery and accessibility require further implementation.
