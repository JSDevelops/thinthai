# ร้านค้าและรัศมีจัดส่ง — 5 ตุลาคม 2026

## วิธีใช้งาน

1. เปิด http://127.0.0.1:3200 และเข้าสู่ระบบด้วยบัญชีผู้ประกอบการ, Admin หรือ Super Admin
2. กด “เพิ่มร้านค้า” กรอกชื่อ หมวด จังหวัด อำเภอ ตำบล และที่อยู่
3. แตะแผนที่ ลากหมุด หรือกรอกละติจูด/ลองจิจูด แล้วกด “บันทึก”
4. แก้ชื่อ ที่อยู่ หมวด ตำแหน่ง และเปิด/พักร้านจากปุ่ม “แก้ไขร้าน”
5. Admin/Super Admin กด “ตั้งค่าจัดส่ง” บนร้านอาหาร เลือกเปิดจัดส่งและรัศมี 0.1–30 กม. แล้วบันทึก
6. เปิดการตั้งค่าอีกครั้ง เลือกจุดบนแผนที่หรือกรอกพิกัดปลายทาง แล้วกด “ตรวจพื้นที่” เพื่อตรวจโซนที่บันทึกไว้
7. กด “ประวัติ” เพื่อดูผู้แก้ไข เวลา และสถานะหลังแก้ไข 50 รายการล่าสุด

## สิทธิ์และกฎ

- USER สร้างหรือจัดการร้านไม่ได้
- MERCHANT สร้างร้านเพิ่มได้และได้สมาชิกของร้านใหม่นั้นโดยอัตโนมัติ แก้ได้เฉพาะร้านที่ตนมีสิทธิ์
- ADMIN สร้าง/แก้/ตั้งค่าจัดส่งเฉพาะจังหวัดที่ได้รับมอบหมาย รวมการตรวจจังหวัดปลายทางเมื่อย้ายร้าน
- SUPER_ADMIN จัดการทุกร้านได้
- ร้านที่ Admin สร้างยังไม่มีผู้ประกอบการรับมอบหมาย ต้องเพิ่ม workflow อนุมัติและมอบร้านในระยะถัดไป
- เปิดจัดส่งได้เฉพาะร้านอาหารที่เปิดร้านและมีพิกัดทั้งสองค่า
- เปลี่ยนหมุด ตำบล หมวด หรือสถานะร้านจะปิดจัดส่งเดิมและล้างรัศมี ให้ Admin ตรวจใหม่
- สินค้าชุมชนไม่ถูกนำเข้าโซนอาหารและตั้งค่าจัดส่งอาหารไม่ได้
- ทุกการเขียนอยู่ใน transaction เดียวกับประวัติ พร้อม version ป้องกันข้อมูลทับกัน หากข้อมูลเก่าให้ปิดฟอร์มและเปิดใหม่
- ไม่มีการลบร้าน ใช้พักร้านเพื่อรักษาข้อมูลและประวัติ

## ขอบเขตปัจจุบัน

รัศมีใช้ระยะ great-circle โดยสูตร Haversine ไม่ใช่ระยะขับรถ ไม่ได้คำนวณค่าส่งหรือเวลาจัดส่ง และยังไม่เชื่อม checkout/คนขับ

ข้อมูลพื้นที่เป็นตัวอย่างเชียงใหม่และสมุทรสงคราม ยังไม่ครบประเทศ ไม่มี polygon ขอบเขตจังหวัด/ตำบล จึงตรวจได้เฉพาะความสัมพันธ์รหัสพื้นที่ ไม่สามารถยืนยันอัตโนมัติว่าหมุดอยู่ในตำบลที่เลือก ต้องตรวจหมุดก่อนเปิดจัดส่ง

ใช้ Leaflet และภาพแผนที่ OpenStreetMap ผ่าน browser มี attribution ไม่มี bulk download/offline maps เปลี่ยนผู้ให้บริการได้ด้วย NEXT_PUBLIC_MAP_TILE_URL (ต้องแก้ attribution ให้ตรงผู้ให้บริการด้วย) ดู [นโยบายแผนที่](https://operations.osmfoundation.org/policies/tiles/) และ [Leaflet API](https://leafletjs.com/reference)

หากอินเทอร์เน็ตหรือภาพแผนที่ใช้ไม่ได้ ยังกรอกพิกัดด้วยมือและบันทึกได้ ภาพแผนที่เป็นบริการภายนอก ไม่รวมการรับประกัน availability

## API / ฐานข้อมูล

Migration 003 เพิ่ม address, active, version, delivery_enabled, delivery_radius_km และ store_history พร้อมข้อบังคับ food-only ในฐานข้อมูล

- GET /api/v1/areas — พื้นที่ให้เลือกตามสิทธิ์
- POST /api/v1/stores — สร้างร้าน
- POST /api/v1/stores/:id — แก้ร้านพร้อม version
- POST /api/v1/stores/:id/delivery — บันทึกเปิด/ปิดและรัศมีพร้อม version
- POST /api/v1/stores/:id/delivery/check — ตรวจพิกัดกับค่าที่บันทึก
- GET /api/v1/stores/:id/history — ประวัติร้านตามสิทธิ์

ตรวจระบบด้วย npm run test:integration และ npm run test:stores-ui (เปิด npm run dev ไว้ก่อน) UI test สร้างร้านชื่อเฉพาะการทดสอบแล้วลบเฉพาะร้านเหล่านั้นหลังทดสอบ ไม่แตะร้านที่ผู้ใช้สร้าง ภาพพื้นหลังแผนที่ถูกจำลองระหว่าง automated test เพื่อไม่ยิง tile สาธารณะจาก headless browser; geometry/click/marker เป็น Leaflet จริง
