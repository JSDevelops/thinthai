# วิเคราะห์และระบบลงทะเบียน — 5 ตุลาคม 2026

## ผลตรวจระบบเดิม
บัญชีใหม่ถูกกำหนดเป็น USER ฝั่งเซิร์ฟเวอร์ ไม่รับ role จากผู้สมัคร มี password hash, persistent session, rate limit และการแยกสิทธิ์ร้าน/จังหวัด แต่ยังไม่มีช่องทางขอเปิดร้าน ทำให้สมาชิกทั่วไปไปต่อเป็นผู้ประกอบการไม่ได้

## เพิ่มแล้ว
- ยืนยันรหัสผ่านในหน้าสมัครสมาชิก ตรวจความตรงกันก่อนส่งข้อมูล
- เมนูสมัครผู้ประกอบการสำหรับ USER/MERCHANT และตรวจคำขอเปิดร้านสำหรับ Admin/Super Admin
- กรอกชื่อร้าน หมวด จังหวัด อำเภอ ตำบล ที่อยู่และเบอร์ติดต่อ
- ฉบับร่าง → รอตรวจ → ขอแก้ไข → ส่งตรวจใหม่ → อนุมัติ/ไม่อนุมัติ พร้อมเหตุผลและประวัติ
- ผู้สมัครเห็นเฉพาะคำขอของตน แก้ได้เฉพาะฉบับร่างหรือขอแก้ไข
- มีคำขอที่ยังไม่สิ้นสุดได้คนละหนึ่งรายการ คำขออนุมัติ/ไม่อนุมัติแล้วแก้ต่อไม่ได้
- ผู้ดูแลไม่เห็นฉบับร่างและเข้าถึงเฉพาะจังหวัดที่รับผิดชอบ ห้ามอนุมัติตนเอง
- อนุมัติสร้างร้าน สร้างสมาชิก และเปลี่ยนสถานะใน transaction เดียว ใช้ row lock/version ป้องกันสร้างร้านซ้ำจากการกดพร้อมกัน
- ร้านใหม่พักร้านและไม่เปิดจัดส่ง ผู้ประกอบการต้องตั้งค่าร้านและหมุดต่อ
- สิทธิ์ MERCHANT ได้จากสมาชิกของร้านในฐานข้อมูล ไม่ใช่การเปลี่ยน role ที่ฝั่งหน้าจอ

## ทดลองใช้งาน
เปิด http://127.0.0.1:3200 สมัครสมาชิกทั่วไปหรือใช้ USER จาก .local/dev-accounts.md → สมัครผู้ประกอบการ → ยื่นคำขอเปิดร้าน → บันทึกฉบับร่าง → ส่งตรวจ

เปิดอีก browser profile หรือออกจากระบบก่อนเข้าบัญชี Admin ในพื้นที่ → ตรวจคำขอเปิดร้าน → ตรวจคำขอ → เลือกผลและกรอกเหตุผล → ยืนยันผลตรวจ

กลับเข้าบัญชีผู้สมัคร → โหลดข้อมูลล่าสุด → หากอนุมัติ กดอัปเดตสิทธิ์เพื่อจัดการร้าน → เมนูร้านค้า

## ผลตรวจสอบ
API integration รวม 18 กรณีผ่าน มีกรณี draft privacy, owner-only, ข้ามจังหวัด, ข้อมูลที่แอบส่ง status, คำขอซ้ำ, แก้ไขแล้วส่งใหม่, อนุมัติพร้อมกัน, ปฏิเสธ, อนุมัติตนเอง, session รับสิทธิ์ใหม่และข้อมูลคงอยู่หลัง restart

UI ทดสอบสมัครบัญชีจริงในเครื่อง (รวมรหัสผ่านยืนยันผิด), ยื่นคำขอ, ส่งตรวจ, Admin อนุมัติ และผู้สมัครเห็นร้าน ครบเส้นทาง ไม่มี page error ตรวจฟอร์ม desktop 1440, tablet 820, mobile 390 ไม่ล้นแนวนอน ภาพอยู่ design/previews/registration

รันทดสอบซ้ำด้วย npm run test:integration และ npm run test:registration-ui (เปิดเว็บ/API ก่อน) บัญชีและร้านที่การทดสอบหน้าจอสร้างจะถูกลบเฉพาะของการทดสอบเมื่อจบ

## สิ่งที่ยังต้องพัฒนา
- ยืนยันอีเมลและเบอร์ กู้บัญชี และ MFA ผู้ดูแล
- แนบเอกสาร/ตรวจไฟล์และขั้นตอนตรวจตัวตนจริง (ปัจจุบันเป็นการพิจารณาข้อมูลร้าน ไม่ใช่ KYC)
- ข้อมูลพื้นที่ครบประเทศ, การมอบหมาย Admin, การเชิญสมาชิกและโอนร้าน
- Pagination (คำขอแสดงล่าสุดไม่เกิน 100 และประวัติ 50), แจ้งเตือน, ถอนคำขอ, retention และการจัดการข้อมูลส่วนบุคคล
- ผู้ประกอบการที่มีสิทธิ์อยู่แล้วใช้เมนูเพิ่มร้านเดิมได้ตามขอบเขตปัจจุบัน หากทุกสาขาต้องผ่านอนุมัติ ต้องเปลี่ยน policy การสร้างร้านเพิ่มเติม

Migration 004 เพิ่ม merchant_applications และ application_history ไม่แก้ข้อมูลร้านเดิม ระบบยังจำกัดใช้งานในเครื่อง
