# ตารางสิทธิ์เป้าหมาย — ต้องบังคับฝั่งเซิร์ฟเวอร์

ตารางนี้เป็นข้อกำหนดเป้าหมาย ไม่ใช่สิทธิ์ทั้งหมดที่ implement แล้ว

| การกระทำ | ลูกค้า | เจ้าของ/ทีมธุรกิจ | Adminพื้นที่ | การเงิน | Super Admin |
|---|---|---|---|---|---|
| โปรไฟล์/ที่อยู่ | ของตน | ของตน | เท่าที่จำเป็นในงานช่วยเหลือ | ไม่ให้โดยปริยาย | เฉพาะกรณีที่อนุญาตและมีaudit |
| สินค้า/ทริป/ที่พัก | ดูรายการเปิดขาย | เฉพาะธุรกิจ/สาขาและactionที่ได้รับ | พื้นที่+บริการที่ได้รับ | อ่านข้อมูลอ้างอิงธุรกรรม | ตามactionที่ได้รับ |
| สร้างคำสั่งซื้อ/จอง | ของตน | ในฐานะลูกค้าของตน | ไม่สร้างแทนผ่านcustomer endpoint | ไม่สร้างแทน | ไม่สร้างแทนผ่านcustomer endpoint |
| payment customer API | ของตน | ของตนในฐานะลูกค้า | ไม่มีทางลัดข้ามเจ้าของ | ใช้finance endpointเฉพาะ | ไม่มีทางลัดข้ามเจ้าของ |
| รายการร้าน | ของตน | ร้าน+สาขาของตน | พื้นที่+บริการ+action | เฉพาะการเงินที่มอบหมาย | ตามaction |
| คืนเงิน/โอนเงิน | ส่งคำขอของตน | ส่งคำขอตามสิทธิ์ | ไม่ได้โดยปริยาย | จัดทำ/อนุมัติแยกคน | ไม่ข้ามขั้นอนุมัติโดยเงียบ |
| ตั้งเขตส่งอาหาร | ไม่มี | ขอแก้ไข | เฉพาะอาหารในscope | ไม่มี | ตามสิทธิ์ |
| เพิ่มสิทธิ์ทีม | ไม่มี | เฉพาะร้านและเพดานตน | ไม่ได้โดยปริยาย | ไม่มี | จัดการพร้อมเหตุผล+audit |

ไรเดอร์เห็นเฉพาะงานที่เสนอ/รับและข้อมูลลูกค้าที่จำเป็นในช่วงงาน; Creatorเห็นผลงานและรายได้ของตน ทีมดูแลเนื้อหาเห็นเฉพาะงานที่มอบหมาย

ทุก list/detail/export/file URL/background job ต้องตรวจ scope การซ่อนปุ่มไม่เพียงพอ default deny, ไม่เชื่อ store_id/role จาก client, ถอนสิทธิ์แล้วsessionเดิมต้องไม่มีอำนาจเดิม

กรณีทดสอบ: ร้านAห้ามอ่าน/แก้ร้านB; AdminจังหวัดAห้ามจังหวัดB; actionอ่านห้ามเขียน; ผู้ประกอบการห้ามยกระดับตน; paymentข้ามเจ้าของห้ามแม้Admin; เปลี่ยนรหัสผ่าน/ถอนสิทธิ์แล้วsessionต้องมีพฤติกรรมตามนโยบาย; foodzoneปิดไม่ปิดทริป/ที่พัก/สินค้า
