# จัดการสินค้า — 5 ตุลาคม 2026

## วิธีใช้งาน
1. เปิด http://127.0.0.1:3200 เข้าบัญชีผู้ประกอบการหรือผู้ดูแล แล้วเลือกเมนู “สินค้า”
2. เลือกร้าน → เพิ่มสินค้า → กรอกชื่อ รายละเอียด ราคา หมวด วิธีรับสินค้า และสต๊อกเริ่มต้น → บันทึกสินค้า
3. หลังสร้างสินค้า เลือกรูปแล้วกดบันทึกรูป รองรับรูปปก 1 รูปต่อสินค้า เปลี่ยนหรือลบรูปได้
4. ปรับสต๊อกด้วยจำนวนบวก/ลบพร้อมเหตุผล เช่น รับของ +10 หรือเสียหาย -2 ทุกครั้งมีประวัติ
5. เลือกเปิด/ปิดขายและบันทึก ดู “หน้าสินค้าสำหรับลูกค้า” ที่ /catalog เพื่อตรวจสิ่งที่ลูกค้าเห็น
6. สินค้าส่งอาหารทันทีมีช่องตรวจพิกัดปลายทางในหน้าสินค้าลูกค้า

## กฎการแสดงและสิทธิ์
- ผู้ประกอบการจัดการสินค้าได้เฉพาะร้านที่เป็นสมาชิก Admin ตามจังหวัด Super Admin ทุกจังหวัด
- สินค้าเปิดขาย ร้านเปิด และสต๊อกมากกว่า 0 จึงแสดงใน catalog
- หมวด food/craft แยกจากวิธีรับสินค้า: instant_food_delivery / parcel_delivery / pickup
- อาหารแห้งส่งพัสดุได้โดยไม่ใช้โซนอาหาร
- ส่งอาหารทันทีต้องเป็นสินค้าอาหารในร้านอาหาร และต้องเปิดโซนร้าน จึงแสดงใน catalog
- ตรวจระยะเฉพาะ instant_food_delivery จากหมุดและรัศมีล่าสุดของร้าน สูตร Haversine เช่นเดิม ไม่ใช่เส้นทางขับรถ
- ไม่ลบสินค้า ใช้ปิดขายเพื่อคงประวัติ

## ความถูกต้องของข้อมูล
ราคาเก็บจำนวนเต็มหน่วยสตางค์ ช่วง 0.01–1,000,000 บาท สต๊อกจำนวนเต็ม 0–1,000,000 ใช้ transaction/row lock และ version ร่วมกันสำหรับข้อมูลสินค้า รูป และสต๊อก ป้องกันการแก้ทับ

สต๊อกใช้ requestKey ต่อรายการ รองรับการลองคำขอเดิมซ้ำโดยไม่เพิ่ม/ลดซ้ำ ถ้าใช้ key เดิมกับข้อมูลอื่นจะปฏิเสธ ผู้ใช้กรอกเหตุผลอย่างน้อย 3 ตัวอักษร ประวัติเก็บผู้ดำเนินการ เวลา ก่อน/หลัง และจำนวนเปลี่ยนแปลง

## รูปภาพ
รับ JPG / PNG / WebP ไม่เกิน 2 MB และ 16 ล้านพิกเซล ตรวจเนื้อไฟล์ด้วย sharp ไม่เชื่อนามสกุล ปฏิเสธ SVG/ภาพเคลื่อนไหว/ไฟล์เสีย แปลงเป็น WebP ขนาดสูงสุด 1200×1200 ไม่ขยายภาพเล็ก ตัด metadata และจำกัดผลลัพธ์ 1 MB เก็บรูปเดียวใน PostgreSQL ของระยะพัฒนา

ภาพสินค้าที่ไม่พร้อมขายอ่านได้เฉพาะผู้มีสิทธิ์ร้าน ภาพของสินค้าที่แสดง catalog เปิดอ่านได้ การอัปโหลดใช้ session + origin/action header และ rate limit เดียวกับกลไกคำขอของระบบ (10 ต่อ identity ภายใน 15 นาที)

อ้างอิงการตรวจและแปลง: [sharp constructor](https://sharp.pixelplumbing.com/api-constructor/) / [metadata](https://sharp.pixelplumbing.com/api-input/)

## ฐานข้อมูลและ API
Migration 005 เพิ่ม products และ product_history พร้อมข้อบังคับราคา สต๊อก ชนิดวิธีรับสินค้า และขนาดรูป
- GET/POST /api/v1/stores/:id/products
- POST /api/v1/products/:id
- POST /api/v1/products/:id/stock
- GET/POST /api/v1/products/:id/image (POST JSON data=base64 หรือ null เพื่อลบ)
- GET /api/v1/products/:id/history
- GET /api/v1/catalog
- POST /api/v1/catalog/:id/availability

รายการสินค้าล่าสุดสูงสุด 200 รายการต่อหน้า และประวัติ 50 รายการ ยังไม่มี pagination เต็มรูปแบบ

## ทดสอบแล้ว
API integration รวม 22 กรณีผ่าน รวมการปฏิเสธข้ามร้าน ราคาไม่ถูกต้อง สต๊อกติดลบ คำขอซ้ำ การแก้พร้อมกัน ประวัติและ restart, ไฟล์ปลอม/SVG/ใหญ่เกินกำหนด, WebP ที่ไม่มี EXIF, รูปปิดขายไม่รั่ว, การซ่อนร้านพัก/สินค้าหมด และอาหารส่งพัสดุไม่ติดโซน

UI desktop 1440×1000, tablet 820×1180, mobile 390×844 ผ่านเพิ่มสินค้า อัปโหลดรูป ปรับสต๊อก ดู catalog ปิดขาย โหลดใหม่ และประวัติ ไม่มี page errors หรือแนวนอนล้น ภาพประกอบเป็นรูปสีพื้นสำหรับทดสอบ อยู่ design/previews/products

รันซ้ำด้วย npm run test:integration และ npm run test:products-ui (เปิด npm run dev ไว้ก่อน) UI สร้างร้าน/สินค้าทดสอบแล้วลบเฉพาะข้อมูลของการทดสอบเมื่อเสร็จ

## ขั้นถัดไป / ข้อจำกัด
ยังไม่ใช่ระบบซื้อขายจริง ไม่มีตะกร้า การจองสต๊อก ตัดสต๊อกจากคำสั่งซื้อ การชำระเงิน หรือการจองบริการท่องเที่ยว การตรวจ availability ไม่จองสินค้าให้ลูกค้า

รองรับรูปปกเดียวและวิธีรับสินค้าเดียวต่อสินค้าในระยะนี้ ยังไม่มีหลายรูป ตัวเลือกสินค้า/SKU หรือ promotion ก่อนขยายโหลดให้ย้ายรูปไป object storage/CDN เพิ่ม pagination, retention และตรวจความปลอดภัยการอัปโหลดเพิ่มเติม

ยืนยันอีเมล กู้รหัสผ่าน และ MFA ผู้ดูแลยังเป็นงานก่อนเปิดภายนอก ระบบยังจำกัดการรันในเครื่อง
