# ThinThai — คู่มือพัฒนาในเครื่อง

## สถานะปัจจุบัน

Next.js + NestJS เชื่อม PostgreSQL แล้ว บัญชี ร้านค้า สิทธิ์ และเซสชันเก็บในฐานข้อมูล ข้อมูลร้านและพื้นที่ที่ใส่เริ่มต้นเป็นตัวอย่าง ระบบยังเปิดเฉพาะเครื่องนี้ ไม่ใช่ production

## เริ่มต้น

ใช้ Node.js 24, npm 11 และ PostgreSQL 16+ (macOS Homebrew: /opt/homebrew/opt/postgresql@16/bin หรือกำหนด PG_BIN)

```sh
npm ci
npm run db:start
npm run db:migrate
npm run db:seed
npm run dev
```

เปิด http://127.0.0.1:3200 ใช้ URL นี้ให้ตรงกับการตรวจ origin

- เว็บ 3200; API 4200; PostgreSQL 55433 ไม่ใช้ฐานข้อมูลโครงการเก่า
- db:start สร้าง .env ที่มีรหัสผ่านสุ่มและ .local/postgres เฉพาะโครงการนี้
- PostgreSQL ใช้ TCP loopback เท่านั้น รองรับชื่อโฟลเดอร์ภาษาไทยและช่องว่างโดยไม่ติดข้อจำกัดความยาว Unix socket
- db:seed สร้าง 4 บัญชีรหัสผ่านสุ่ม เก็บไว้ใน `.local/dev-accounts.md` สิทธิ์ไฟล์ 0600 และไม่นำเข้า Git ไม่มีการเลือกบทบาทเพื่อเข้าสู่ระบบอีกแล้ว
- seed ซ้ำไม่เปลี่ยนรหัสผ่านและไม่เพิ่มข้อมูลซ้ำ อย่าลบไฟล์บัญชีก่อนเก็บรหัสผ่านอย่างเหมาะสม
- สมัครสมาชิกผ่านหน้าเว็บได้ บัญชีใหม่เป็น USER เสมอ
- เข้าสู่ระบบคงอยู่หลัง refresh และ API restart; ออกจากระบบเพิกถอนเซสชันนั้น; เปลี่ยนรหัสผ่านเพิกถอนทุกเซสชัน
- ปิดเว็บ/API ด้วย Ctrl+C แล้ว `npm run db:stop` เมื่อไม่ใช้ฐานข้อมูล

## ตรวจสอบ

```sh
npm test
npm run test:integration
npm run typecheck
npm run build
# เปิด npm run dev ไว้อีกหน้าต่าง แล้วใช้ Chrome ที่ติดตั้งในเครื่อง
npm run test:ui
```

API integration ใช้ `thinthai_test` และพอร์ต 4201 โดยตรวจชื่อฐานข้อมูลก่อนล้าง fixture ไม่แตะ `thinthai_dev` ส่วน UI ใช้บัญชี seed และสร้างสมาชิกชั่วคราวของการทดสอบเองแล้วลบออก ภาพบันทึกใน design/previews/auth

ทดสอบแบบ UI หลายครั้งติดกันอาจชน rate limit ที่ตั้งไว้ ต้องรอ 15 นาทีตามข้อความ ไม่ลดการป้องกันของแอปเพื่อให้ทดสอบผ่าน

## สิทธิ์

USER ดูบัญชีตนเอง; MERCHANT เห็นร้านตาม store_memberships; ADMIN เห็นเฉพาะจังหวัดที่มอบหมาย; SUPER_ADMIN เห็นทุกร้าน บันทึกร้าน พิกัด และโซนรัศมีอาหารได้แล้ว อ่าน [วิธีจัดการร้านค้า](STORE_MANAGEMENT.md)

## ขั้นถัดไป

การอนุมัติผู้ประกอบการ/มอบร้าน → ข้อมูลพื้นที่ครบประเทศและโซน polygon PostGIS → สินค้าและการจอง

ก่อนเปิดภายนอกยังต้องมีการยืนยันอีเมล การกู้บัญชี MFA สำหรับผู้ดูแล HTTPS การจัดการ secret การสำรอง/กู้คืนฐานข้อมูล และการตรวจความปลอดภัย โค้ดจึงยังปฏิเสธ NODE_ENV=production

## เส้นทางใช้งานปัจจุบัน (5 ตุลาคม 2026)

หน้าแรก `/` เป็นเว็บท่องเที่ยวสาธารณะ เข้าสู่ระบบและหลังบ้านที่ `/workspace`
ซื้อสินค้าที่ `/catalog`, คำสั่งซื้อ `/orders`, ค้นหาทริป `/trips`, การจอง `/bookings`
รัน `npm run db:migrate` ก่อนเริ่ม API เพื่อใช้ migration 006–007
เพิ่มทริปตัวอย่างด้วย `npm run db:seed-trips` (ไม่เปลี่ยนบัญชีหรือทริปเดิม)
ทดสอบ UI ใหม่ด้วย `npm run test:orders-ui` และ `npm run test:trips-ui`
